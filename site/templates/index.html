── What's a TSO? ──

A timestamp oracle is a service that hands out strictly increasing integer IDs which order events across a distributed system. You reach for one when you're building a database with MVCC, merging change-data from many shards, or maintaining audit logs with a real happens-before relation across machines.

Per-host wall clocks aren't monotonic enough. Database sequences don't scale across shards. A TSO is the canonical answer — and the one Spanner, CockroachDB, and FoundationDB all use internally.

→ Read: Why distributed systems need a TSO

── Features ──
Strictly monotonic

Every issued timestamp is strictly greater than every previous one. No duplicates, no regression.

Crash-safe

Window state is fsync'd before any timestamp from it is handed out. Restarts never rewind.

Pluggable consensus

Production openraft driver included. One trait to back tsoracle with raft-rs, etcd, or your own log.

gRPC client included

Leader discovery, request coalescing, reconnection — handled. Just call get_ts().

── How it works ──
client ──get_ts(batch=N)──► leader ──[fsync]──► local window
                                │
                                └──replicate via raft──► followers
client ◄────window range [a, a+N)─── leader

A single round-trip allocates a batch of N IDs. The leader fsyncs the new high-water mark and replicates it through raft before the range leaves the process. Clients hand out IDs from the batch locally — millions per second on commodity hardware.

── Get started ──
$ cargo install tsoracle
$ tsoracle serve

# Listens on 127.0.0.1:50551
# Persists state to ./tsoracle-data/
use tsoracle_client::Client;

let client = Client::connect(
    vec!["http://127.0.0.1:50551".into()]
).await?;

let ts = client.get_ts().await?;
let batch = client.get_ts_batch(64).await?;

Want to embed the server in your own binary? See the embedded-server example.
